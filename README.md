# 再構成損失で、円の動きの読み取りやすさは変わるか

時刻 t−Δ と t の2枚の画像を畳み込みオートエンコーダで圧縮し、固定したエンコーダの潜在表現から円の位置、速度、5フレーム先の位置を予測する実験です。再構成画像をクリーン画像と比較した PSNR と、各予測のテスト R² を別々に記録します。実測値・学習率の選択・今回の停止位置は [REPORT.md](REPORT.md) を参照してください。

## 環境

検証環境は Python 3.13.5、Apple Silicon の macOS です。以下はリポジトリのルートで実行します。

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
```

自動選択の優先順位は CUDA、Apple MPS、CPU です。CUDA では使用する PyTorch と互換性のあるドライバが必要です。データはその場で生成するため、動画のダウンロードは不要です。乱数・計算順・バックエンドを固定し、同一環境での再現を検証します。異なるデバイスや PyTorch のバージョン間でのビット一致は前提にしません。

## 実験の順序

```sh
python run_sweep.py --calibrate-only --steps 300   # ステージ0用の学習率比較
python run_sweep.py --stage 0             # 時間・メモリ計測。ここで終了
```

過去の Δ=1 ステップ数診断では、クリーンな r=5 のみで速度情報を調べました。次のコマンドは当時の診断と再構成損失による学習率比較用です。

```sh
python diagnose_steps.py                            # 3シード × 4測定点の学習・評価
python diagnostic_probes.py --raw-baseline          # 生画像2枚から直接、速度を回帰
python run_sweep.py --calibrate-only --steps 3000   # 全4損失 × 3候補で学習率を再選定
```

診断はどの測定点でもステージ0で選んだ L2 学習率 **0.003** を使います。同じ学習系列の 300、1,000、3,000、10,000 ステップで評価したところ、速度の MLP R² は10,000までに頭打ちを確認できませんでした。本実験用の **3,000ステップは計算時間を考慮した予算** です。この旧比較で再構成損失を基準に選んだ学習率は、L1 が 0.0003、L2 と Huber が 0.003、Charbonnier が 0.001 です。各シードの値と判断根拠は [REPORT.md](REPORT.md) にあります。

`diagnose_steps.py` は途中の重み・Adam・乱数状態を `checkpoints/step_diagnostic/` に保存し、同じコマンドの再実行で再開できます。学習と評価を分けるには `--train-only`、次に `--evaluate-only` を指定します。診断の数値は `results/runs.jsonl` の `purpose="step_diagnostic"`、生画像対照は `results/raw_velocity_baseline.json` に入ります。すでに数値を収録した環境では、診断と学習率比較は完了済み行をスキップします。

過去の Δ=1 の健全性テストでは、半径8の速度MLP R² が −0.00948 で、追加した閾値 > 0.8 に届きませんでした。当時の実測は26件通過・1件不合格です。

### フレーム間隔 Δ と学習率の選定

```sh
python gap_study.py --selection                       # Δ=1,2,4,8 × r=2,5,8 × 5シード
python gap_study.py --calibrate-only                  # 合格した最小のΔで、4損失 × 3学習率 × 3シード
python summarize_gaps.py                              # Δ別のシード表・成功率の図を出力
python estimate_stages.py                             # 実測時間からステージ別の所要時間を推定
python -m pytest -q -s -rs tests/test_training.py::test_large_clean_velocity
```

全60件の測定後、r=5 と r=8 の両方について **全5シード** で速度の MLP R² > 0.8 となる最小の Δ を選びます。どの Δ も合格しなかった場合、学習率の再選定と新しい速度チェックは未実行になります。通常のステージ1〜3も適格な Δ と学習率を読み込めるまで起動しません。

各損失で学習率候補を比較するときは、3シードで平均した速度 MLP R² が最良値から 0.01 以内の候補を残します。その中から平均位置 MLP R² が最良値から 0.01 以内の候補を残し、平均 PSNR が最大の候補を採用します。すべて同値なら小さい学習率を採用します。プローブ学習／採点のデータ系列は、Δ選定が2/3、学習率比較が4/5、本実験と新しい速度チェックが6/7です。各番号 k は独立した乱数種 `SeedSequence([k, 0])` を表します。学習率比較のAEシードは 1729, 1730, 1731 です。

### 本実験の起動

ステージ1〜3は未実行です。採用条件で後日実施する場合、通常の各コマンドはプローブで選んだ損失別の学習率と3,000ステップを使います。

```sh
python run_sweep.py --stage 1
python run_sweep.py --stage 2
python run_sweep.py --stage 3
python plot.py

# ステージ1限定の感度分析。通常のステージ1には含めない。
python run_sweep.py --stage 1 --shared-lr
python plot.py --shared-lr
```

感度分析では全半径、全4損失、各5シードを、同じ学習率 0.001 で比較します。主比較との間で学習率を含む設定が同じなら、同じ実測行を利用します。Δが選ばれなかった後に明示的に間隔 D を指定して別の感度分析を行う場合のみ、`--stage 1 --shared-lr --frame-gap D` が使えます。通常の本実験では該当するΔのプローブ学習率比較が必要です。

## データと評価の読み方

- データの形は `[バッチ, 2, 64, 64]`。チャネルは t−Δ、t の順です。旧ステージ0は Δ=1 です。ラベルは `(x, y, vx, vy, x5, y5)`、位置の単位は px、速度は px/フレーム。半径まで考慮して壁で反射させ、未来位置も同じ反射規則で求めます。円の中心は連続値で、境界画素に部分的な明るさを与えます。
- clean の背景は 0.3、円の内部は 1.0。ガウスノイズは加算後にクリップせず、salt & pepper は確率 p で画素を 0 / 1 に等確率で置換します。both は入力と教師で別々にノイズを引きます。評価用入力にも、その条件の入力ノイズが入ります。
- プローブの学習は10,000例、評価は独立な5,000例で行います。位置、速度、未来位置の順に、各軸で求めた R² の算術平均を示します。R² は一定値を予測する基準と比べて悪い場合は負になります。表示時にもゼロで切り上げません。
- PSNR は2フレーム・全評価画素をまとめたクリーン画像との MSE から `−10 log10(MSE)`（基準値域1）で計算します。小さな円が消えても広い背景をうまく再構成すれば PSNR は高くなり得るため、物体と背景の MAE、中心輝度の背景との差も併記します。

## 学習・検証の条件

Adam、バッチ128、潜在16次元を全条件で共通にします。ステージ1〜3では各設定あたり3,000ステップ（384,000例）、過去のステージ0では300ステップ（38,400例）です。エンコーダのチャネル数は 2→8→16→24→32、各層はカーネル4・ストライド2・パディング1で、4×4の特徴マップを全結合で潜在表現に変換します。デコーダは全結合と4段の転置畳み込みで2枚を再構成します。中間層に GroupNorm と LeakyReLU を使い、入力から既知の背景定数を引き、出力に同じ定数を足します。出力のクリッピングやラベルによるエンコーダ学習はしません。この初期化を含め全損失で構造は共通です。

L2 は平均二乗誤差、L1 は平均絶対誤差、Huber は δ=0.1、Charbonnier は `mean(sqrt(error² + 0.001²))`。旧ステージ0のパイロットは seed=1729 と1,024サンプルの独立検証損失で学習率を選びました。新しい本実験の主比較では、選定した Δ とプローブで選んだ損失別学習率を使用します。学習率を固定した場合の差はステージ1の感度分析で確認できます。本実験ではステージ1・2が seed=0〜4、ステージ3が seed=0〜2 で、同じ半径・シードでは初期重みと運動系列を損失間で揃えます。

リッジ回帰は α=1 で切片を罰しません。MLP は隠れ層64×2・ReLU、Adam、学習率0.001、バッチ256、80エポックで、6つのラベルを同時に予測します。潜在表現と各ラベルをプローブ学習集合の平均・標準偏差で標準化し、テストにはその値を適用します。画像側の MAE は円と面積の重なりがある全画素（境界を含む）と、それ以外で別々に集計します。中心のコントラストは両時刻の真の中心で再構成値を双線形補間し、各フレームの再構成背景の平均を引いたものです。

| ステージ | 対象 | ステージ単独での異なる設定数 |
|---|---|---:|
| 0 | r=5、ノイズなし、L2、seed=0 | 1 |
| 1 | 半径5種、ノイズなし、L1/L2、各5シード | 50 |
| 1・感度分析（任意） | 半径5種、ノイズなし、全4損失、共通学習率0.001、各5シード | 100 |
| 2 | r=5、target_only、両ノイズの全レベル、L1/L2、各5シード。salt_pepper が先 | 100 |
| 3 | 全半径でステージ2相当（300件）＋下記代表点（30件） | 330 |

ステージ3の代表点は r=5、σ=0.2 / p=0.2 の2条件で、Huber の target_only と、L1/L2 の input_only・both を各3シード。Charbonnier は学習率比較と任意の共通学習率感度分析に含めます。ステージ1→2→3の主比較の追加設定数は 50＋90＋246＝386 件です。感度分析は、主比較の L1・L2 のうち採用学習率が 0.001 だった損失1つにつき25設定が重複します。

## 設定と再開

`--device auto|mps|cuda|cpu`、`--latent-dim 4|16|64`、`--steps`、`--background`、`--foreground` を指定できます。件数だけの確認は例として `python run_sweep.py --stage 2 --dry-run`。ステージ1〜3は `gap_study.py` の選定結果を使います。Δまたは学習率の測定が未完了なら理由を表示して終了します。パイロット前にステージ0だけを呼んだ場合は暫定値0.001を使い、その旨を表示します。上記の順序なら選んだ学習率で計測します。

完了した設定だけを `results/runs.jsonl` に追記します。新しい本実験はフレーム間隔と独立した評価データの手順を含むため、見かけの設定が一致する場合も以前の診断結果を本実験の行として使いません。設定、目的（学習率選定／本実験）、手順の版、計算デバイスとライブラリの版から SHA-256 を計算します。ステージ番号はハッシュに含めず、ノイズ量0は種別によらず同じキーにするため、既存の同じ実験はステージをまたいで再利用します。中断後は同じコマンドを再実行してください。完了済みの設定をスキップし、中断した1設定だけは最初から計算します。ステージ1〜3では動画・途中の重みを保存せず、診断用のチェックポイントは Git の対象外にします。新しいプロトコルに変更する際は `run_sweep.PROTOCOL` も変えてください。

## 反射があるときの速度ラベル

速度ラベルは t における物理速度（壁にちょうど達した瞬間は反射後の速度）で、2枚の中心の差とは限りません。例えば r=2 の右壁での反射位置は x=61.5。x が 60.5 → 60.0 と観測されたとき、速度 −0.5 で直接移動した場合と、+2.5 で壁に向かい反射して −2.5 になった場合は同じ2枚になります。5フレーム先はそれぞれ 57.5 と 47.5 です。したがって理想的に中心を読めても、一部の例では速度・未来位置を一意に決められません。仕様どおりこれらも評価に含めます。

## テストと図

```sh
python -m pytest -q -s
python plot.py
```

r=8 の位置チェック（> 0.95）と再現性確認は、既存条件の Δ=1、3,000ステップ、L2 学習率0.003で行います。追加の速度チェックは選定済みの Δ と L2 学習率を使い、seed=0、速度 MLP R² > 0.8 を判定します。Δの合格条件を満たさない場合の速度チェックは `skipped / 未実行` です。過去の不合格結果は [REPORT.md](REPORT.md) に残ります。元の300ステップで当時のチェックだけを再現する場合は `AE_SANITY_STEPS=300 AE_SANITY_LR=0.003 python -m pytest -q -s tests/test_training.py -k "not test_large_clean_velocity"` を使います。

`python plot.py` は全60件がそろっていれば、まず Δ 選定の成功率を `figures/gap_selection_success.png` に描きます。主比較の実測だけを `figures/steps_N/gap_D/main/` に描きます。感度分析には `python plot.py --shared-lr` を使い、別ディレクトリに出力します。旧ステージ0は `python plot.py --historical` で `figures/` に再生成できます。主比較と感度分析には位置・速度のリッジ／MLP別に、中央値と「R² > 0.8 だったシードの割合」のヒートマップが加わります。平均の図は標本標準偏差（分母 n−1）を併記し、L1−L2 は両方あるシードで差を取ります。n はそのセルで評価できた数、灰色は未実行／差を計算できないセルです。

各出力先の `seed_summary.json` に条件別の予定シード、観測数、各シードの全指標、位置・速度R²の中央値、成功数・成功率を保存します。成功率の分母は観測シード数です。未実行の中央値・率は `null`、部分的なセルは `complete: false` として区別します。通常の `python plot.py` はステージ1〜3の和集合を取り、測定数が増えたセルには5シードすべてを含め、ステージ3のみのセルは最大3シードです。半径やノイズ条件間でシードをそろえて比べるには `python plot.py --stage 3` を使います。ステージ3が予定するセルと seed=0、1、2 に限定し、同一設定で既に他ステージで得た実測も利用します。フィルタ後の図とシード表は別の `stage_3/` に保存します。ノイズ量0は両ノイズで共通の測定を参照します。
