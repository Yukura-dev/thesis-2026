# 再構成損失で、円の動きの読み取りやすさは変わるか

連続する2枚の画像を畳み込みオートエンコーダで圧縮し、固定したエンコーダの潜在表現から円の位置、速度、5フレーム先の位置を予測する実験です。再構成画像をクリーン画像と比較した PSNR と、各予測のテスト R² を別々に記録します。実測値・学習率の選択・今回の停止位置は [REPORT.md](REPORT.md) を参照してください。

## 環境

検証環境は Python 3.13.5、Apple Silicon の macOS です。以下はリポジトリのルートで実行します。

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
```

自動選択の優先順位は CUDA、Apple MPS、CPU です。CUDA では使用する PyTorch と互換性のあるドライバが必要です。データはその場で生成するため、動画のダウンロードは不要です。乱数・計算順・バックエンドを固定し、同一環境での再現を検証します。異なるデバイスや PyTorch のバージョン間でのビット一致は前提にしません。

## 実験の順序

```sh
python run_sweep.py --calibrate-only --steps 300   # ステージ0用の学習率比較
python run_sweep.py --stage 0             # 時間・メモリ計測。ここで終了
```

ステージ0の後に、クリーンな r=5 のみで速度情報を診断しました。次のコマンドで同じ診断・学習率比較・r=8 のチェックを再現できます。

```sh
python diagnose_steps.py                            # 3シード × 4測定点の学習・評価
python diagnostic_probes.py --raw-baseline          # 生画像2枚から直接、速度を回帰
python run_sweep.py --calibrate-only --steps 3000   # 全4損失 × 3候補で学習率を再選定
python -m pytest -q -s tests/test_training.py       # r=8の位置・速度と再現性
```

診断はどの測定点でもステージ0で選んだ L2 学習率 **0.003** を使います。同じ学習系列の 300、1,000、3,000、10,000 ステップで評価したところ、速度の MLP R² は10,000までに頭打ちを確認できませんでした。本実験用の **3,000ステップは計算時間を考慮した予算** です。3,000ステップの学習率は診断終了後に改めて選びます。各シードの値と判断根拠は [REPORT.md](REPORT.md) にあります。

`diagnose_steps.py` は途中の重み・Adam・乱数状態を `checkpoints/step_diagnostic/` に保存し、同じコマンドの再実行で再開できます。学習と評価を分けるには `--train-only`、次に `--evaluate-only` を指定します。診断の数値は `results/runs.jsonl` の `purpose="step_diagnostic"`、生画像対照は `results/raw_velocity_baseline.json` に入ります。すでに数値を収録した環境では、診断と学習率比較は完了済み行をスキップします。

ステージ1〜3は未実行です。実施する場合は、以下の各コマンドが3,000ステップを使います。

```sh
python run_sweep.py --stage 1
python run_sweep.py --stage 2
python run_sweep.py --stage 3
python plot.py
```

## データと評価の読み方

- データの形は `[バッチ, 2, 64, 64]`。チャネルは古い順です。ラベルは `(x, y, vx, vy, x5, y5)`、位置の単位は px、速度は px/フレーム。半径まで考慮して壁で反射させ、未来位置も同じ反射規則で求めます。円の中心は連続値で、境界画素に部分的な明るさを与えます。
- clean の背景は 0.3、円の内部は 1.0。ガウスノイズは加算後にクリップせず、salt & pepper は確率 p で画素を 0 / 1 に等確率で置換します。both は入力と教師で別々にノイズを引きます。評価用入力にも、その条件の入力ノイズが入ります。
- プローブの学習は10,000例、評価は独立な5,000例で行います。位置、速度、未来位置の順に、各軸で求めた R² の算術平均を示します。R² は一定値を予測する基準と比べて悪い場合は負になります。表示時にもゼロで切り上げません。
- PSNR は2フレーム・全評価画素をまとめたクリーン画像との MSE から `−10 log10(MSE)`（基準値域1）で計算します。小さな円が消えても広い背景をうまく再構成すれば PSNR は高くなり得るため、物体と背景の MAE、中心輝度の背景との差も併記します。

## 学習・検証の条件

Adam、バッチ128、潜在16次元を全条件で共通にします。ステージ1〜3では各設定あたり3,000ステップ（384,000例）、過去のステージ0では300ステップ（38,400例）です。エンコーダのチャネル数は 2→8→16→24→32、各層はカーネル4・ストライド2・パディング1で、4×4の特徴マップを全結合で潜在表現に変換します。デコーダは全結合と4段の転置畳み込みで2枚を再構成します。中間層に GroupNorm と LeakyReLU を使い、入力から既知の背景定数を引き、出力に同じ定数を足します。出力のクリッピングやラベルによるエンコーダ学習はしません。この初期化を含め全損失で構造は共通です。

L2 は平均二乗誤差、L1 は平均絶対誤差、Huber は δ=0.1、Charbonnier は `mean(sqrt(error² + 0.001²))`。学習率の比較はパイロット seed=1729 で行い、1,024サンプルの独立検証損失で各損失の学習率を一度選びます。損失間で学習率が異なる場合、比較は「各損失をこの選択規則で調整したとき」の結果と解釈してください。本実験では seed=0,1,2 を共通にし、同じ半径・シードでは初期重みと運動系列を損失間で揃えます。

リッジ回帰は α=1 で切片を罰しません。MLP は隠れ層64×2・ReLU、Adam、学習率0.001、バッチ256、80エポックで、6つのラベルを同時に予測します。潜在表現と各ラベルをプローブ学習集合の平均・標準偏差で標準化し、テストにはその値を適用します。画像側の MAE は円と面積の重なりがある全画素（境界を含む）と、それ以外で別々に集計します。中心のコントラストは両時刻の真の中心で再構成値を双線形補間し、各フレームの再構成背景の平均を引いたものです。

| ステージ | 対象 | ステージ単独での異なる設定数 |
|---|---|---:|
| 0 | r=5、ノイズなし、L2、seed=0 | 1 |
| 1 | 半径5種、ノイズなし、L1/L2、各3シード | 30 |
| 2 | r=5、target_only、両ノイズの全レベル、L1/L2、各3シード。salt_pepper が先 | 60 |
| 3 | 全半径でステージ2相当（300件）＋下記代表点（30件） | 330 |

ステージ3の代表点は r=5、σ=0.2 / p=0.2 の2条件で、Huber の target_only と、L1/L2 の input_only・both を各3シード。Charbonnier は指定の本比較には含めず、学習率比較では実行します。

## 設定と再開

`--device auto|mps|cuda|cpu`、`--latent-dim 4|16|64`、`--steps`、`--background`、`--foreground` を指定できます。件数だけの確認は例として `python run_sweep.py --stage 2 --dry-run`。ステージ1〜3を単独で呼び、対応する学習率比較がない場合、必要なパイロットから実行します。パイロット前にステージ0だけを呼んだ場合は暫定値0.001を使い、その旨を表示します。上記の順序なら選んだ学習率で計測します。

完了した設定だけを `results/runs.jsonl` に追記します。設定、目的（学習率選定／本実験）、手順の版、計算デバイスとライブラリの版から SHA-256 を計算します。ステージ番号はハッシュに含めず、ノイズ量0は種別によらず同じキーにするため、既存の同じ実験はステージをまたいで再利用します。中断後は同じコマンドを再実行してください。完了済みの設定をスキップし、中断した1設定だけは最初から計算します。ステージ1〜3では動画・途中の重みを保存せず、診断用のチェックポイントは Git の対象外にします。新しいプロトコルに変更する際は `run_sweep.PROTOCOL` も変えてください。

## 反射があるときの速度ラベル

速度ラベルは t における物理速度（壁にちょうど達した瞬間は反射後の速度）で、2枚の中心の差とは限りません。例えば r=2 の右壁での反射位置は x=61.5。x が 60.5 → 60.0 と観測されたとき、速度 −0.5 で直接移動した場合と、+2.5 で壁に向かい反射して −2.5 になった場合は同じ2枚になります。5フレーム先はそれぞれ 57.5 と 47.5 です。したがって理想的に中心を読めても、一部の例では速度・未来位置を一意に決められません。仕様どおりこれらも評価に含めます。

## テストと図

```sh
python -m pytest -q -s
python plot.py
```

r=8・ノイズなし・L2 の同一モデルで、位置の MLP R² > 0.95 と速度の MLP R² > 0.8 を個別に判定します。デフォルトのステップ数と L2 学習率は本実験用に選んだ値です。同じ設定で初期化から学習を繰り返し、重みと評価指標の完全一致も検証します。元の300ステップの設定で当時のチェックを再現する場合は `AE_SANITY_STEPS=300 AE_SANITY_LR=0.003 python -m pytest -q -s tests/test_training.py -k "not test_large_clean_velocity"` を使います。ほかに円の面積・反射、ノイズの独立性、プローブの陽性／シャッフル対照、設計の件数、ハッシュによる再開、シードを対応させた集計を検査します。

300ステップの図は `figures/` に、それ以外の学習ステップ数 N の図は `figures/steps_N/` に出力します。旧ステージ0の図を再生成するコマンドは `python plot.py --steps 300` です。各セルはシード間の平均と標本標準偏差（分母 n−1）です。L1−L2 の R² は両方がそろった同じシードで差を取り、その差を集計します。1シードしかなければ n=1 と表示し、標準偏差は算出しません。灰色は未実行／差を計算できないセルです。ノイズ量0の列は二つのノイズ種で同じデータを参照します。学習率比較や健全性チェックの行は、比較用の図に使いません。
